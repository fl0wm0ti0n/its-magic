# DEC-0155: US-0164 per-gate gate-cause resolution, budget-gate provider fallback, and silent drain handoff

- Date: 2026-10-24
- Status: Accepted
- Story: `US-0164`
- Research: `R-0175` (Q1–Q7 RESOLVED)
- Composes on: DEC-0078 (block-retry ledger), DEC-0124 (stop-matrix JSON response path), DEC-0086 (provider catalog resolution), DEC-0131 (host-neutral config SOT); US-0158 `continue_same_phase` (composition reference). Amends nothing.

## Context

The shared US-0088/US-0092 stop matrix halts an `/auto` run at an active gate; the operator must re-invoke. The operator's locked ask (US-0164): the AI resolves the **cause** of an active gate and continues the **same** run without an operator or auto re-invoke — never the gate itself. The safety floor is non-negotiable in every configuration: `pause_request` and gate-override-forbidden remain hard stops; no `.env` read; no automatic npm publish or git push; `AUTO_SELFRESOLVE_EXCLUDE=pause_request` is hard.

US-0158 (DONE) already established the bounded same-run continue pattern: an optional flag on `run_stop_matrix_json` emitting `continue_same_phase` with one in-memory attempt per `(phaseId, class)`, second hit using the original reason code, parent read-only. US-0101/DEC-0086 already provide the operator-populated local model catalog (`cheap`/`balanced`/`strong` tiers, alias resolution, no hard vendor slug). US-0095 already provides the drain-advance algorithm and its predicate. US-0131/DEC-0131 already provide the host-neutral config SOT chain. This decision adopts the additive composition of those four mechanisms for the per-gate cause-resolution policy — a new normative decision, not a bounded defect remediation, hence a companion DEC (research R-0175 did not decide it).

## Decision

1. **Adopt R-0175 Approach A.** `scripts/auto_outer_driver.py run_stop_matrix_json` gains a NEW optional `--selfresolve-gate <gate_id>` branch, **additive to** (not replacing) the US-0158 `--recoverable-class` branch. Precedence: if `--recoverable-class` is present it wins unchanged; otherwise the self-resolve branch is evaluated. When `gate_id` is in the validated enabled set AND the safety-floor guards pass, the payload is `action=continue_same_phase` + `next_phase=<phase>` — byte-identical to the US-0158 continue branch — so the existing OpenCode plugin respawn-once machinery (one attempt per `(phaseId, gate)`, fresh marker) is reused unchanged. Absent the flag, today's JSON is byte-identical (default-off, US-0156 style).
2. **The driver never inspects, edits, or re-scores the gate.** It only decides continue-versus-stop. The cause resolution itself is performed by the spawned same-phase child (the LLM role). After the child's repair, the **SAME unchanged** gate check re-runs: if it now passes → continue; if it still fails → second hit → `SELFRESOLVE_ATTEMPT_EXHAUSTED` (bounded = one attempt per `(phaseId, gate)`). The gate is never bypassed, weakened, disabled, removed, or threshold-changed (AC-1).
3. **`decision_gate` is propose-and-hold, never auto-continue (AC-1).** It stays in `HARD_STOP_REASONS` and `TERMINAL_CONTINUE_TOKENS`, so no continue branch can fire for it. The same-phase child writes the proposed resolution as an artifact + a names-only `handoffs/auto_block_retry/<orchestrator_run_id>.jsonl` ledger row; the gate re-check still fails (a decision gate by definition requires a decision the AI cannot make); the run **halts with `decision_gate=true` + a non-suppressible notification**. No `decision_gate=false` flip, no auto-flip. The proposal gives the operator the resolution to approve on the next (operator) invoke.
4. **`missing_input` splits transient vs critical (AC-1).** Reuses the existing `_is_recoverable` split: `reason_code in ("critical","CRITICAL_MISSING_INPUT")` → NOT self-resolvable → hard stop (existing behavior, unchanged). Transient → eligible for bounded obtain/derive in the same phase; still missing after one attempt → `SELFRESOLVE_ATTEMPT_EXHAUSTED`. No new critical-missing-input code.
5. **Budget-gate provider fallback: one switch per run, budget counter NOT reset (AC-4).** Budget gates (`loop_max`, `BACKLOG_MAX_STORIES_REACHED`) are NOT in the self-resolve set. When a budget gate fires AND `AUTO_BUDGET_PROVIDER_FALLBACK=1` AND the one-switch-per-run cap is unused, the run performs at most ONE provider switch: the NEXT phase child's model is resolved via the existing US-0101/DEC-0086 catalog + US-0102/DEC-0087 role chain (`scripts/model_tier_lib.py resolve_model_for_phase()`), selecting a DIFFERENT catalog tier/alias than the one that just hit the gate. No hard vendor slug, no new vendors. The switch is recorded in the existing append-only, names-only `handoffs/auto_block_retry/<orchestrator_run_id>.jsonl` ledger with `reason_code=PROVIDER_SWITCH_APPLIED`. Reaching the cap (a second budget-gate hit, or `AUTO_PROVIDER_SWITCH_MAX` (default 1) exceeded) → run stops with `PROVIDER_SWITCH_CAP_REACHED`. **The budget counter is NOT reset after the switch — the remaining budget carries over (PO decision, fail-closed; resetting would let provider cycling manufacture extra budget).** Scope lock: the switch applies ONLY to the model override for the NEXT phase child spawn; the outer driver is model-less Python and the running parent/orchestrator model is unchanged. `MODEL_*` keys remain ignored by `host_runtime_config_lib` (US-0132 boundary) — the switch reads the catalog via `model_tier_lib`, NOT a new `MODEL_*` governance key. Catalog-resolution failure (MODEL_TIER_INVALID / MODEL_CATALOG_INVALID / MODEL_SLUG_UNKNOWN / …) → fail closed: no switch, the budget gate stays a hard stop.
6. **Silent drain handoff `SELFRESOLVE_DRAIN_HANDOFF` (AC-5).** The handoff fires when (a) self-resolve is exhausted (`SELFRESOLVE_ATTEMPT_EXHAUSTED`) OR (b) a budget gate is hit after the provider fallback (`PROVIDER_SWITCH_CAP_REACHED`). It extends the US-0095 drain-advance predicate in addition to `stop_reason=completed`: the run also drain-advances when the stop is the self-resolve-exhausted / budget-cap handoff AND drain is enabled (`AUTO_BACKLOG_DRAIN=1` or bug-queue per the US-0087 mutex) AND an eligible OPEN story exists AND budget remaining. The US-0095 7-step algorithm (READ boundary → ASSERT DEC-0069 pairing → SELECT next per `AUTO_STORY_SELECTION=priority_then_backlog_order` → RELOAD/MATERIALIZE → PREPEND `resume_brief` → APPEND `state.md` breadcrumb → IMMEDIATELY spawn) is reused verbatim; `drain_advance_action=spawned` attestation. `AUTO_BACKLOG_DRAIN=0` or no eligible OPEN story → the run stays a HARD STOP (fail-closed, unchanged): `SELFRESOLVE_DRAIN_HANDOFF` is emitted but the action is `hard_stop` (no drain advance). The handoff is silent (no operator re-invoke, no auto re-invoke).
7. **5-key fail-closed config surface, all default-off (AC-7).** Five new `AUTO_*`-namespaced governance keys: `AUTO_SELFRESOLVE_GATES` (per-gate comma list, default empty; default set when enabled `error,missing_input,decision_gate,security,publish`); `AUTO_SELFRESOLVE_EXCLUDE=pause_request` (hard, cannot be removed, never self-resolved); `AUTO_BUDGET_PROVIDER_FALLBACK=0`; `AUTO_PROVIDER_SWITCH_MAX=1` (max one switch/run); `AUTO_BUDGET_EXHAUSTED_DRAIN=0`. Precedence: host-neutral config SOT chain per US-0131/DEC-0131 (`.its-magic/config.local.json` > `config.json` > `config.example.json`) with the DEC-0055 scratchpad adapter for the Cursor host (`.cursor/scratchpad.local.md` > `.cursor/scratchpad.md` > `.cursor/scratchpad.local.example.md`); read via `host_runtime_config_lib.resolve_runtime_config` (which the outer driver already uses). Unknown gate id in `AUTO_SELFRESOLVE_GATES` → **fail closed, reusing `HOST_CONFIG_INVALID`** (US-0131 config-SOT validation code) with the offending key+value in the detail — NOT a 5th new reason code, NOT silently ignored (AC-3). `MODEL_*` keys stay ignored (US-0132 boundary).
8. **Safety floor preserved in every configuration (AC-2).** `pause_request` and gate-override-forbidden stay in `HARD_STOP_REASONS`; `pause_request` is never in the self-resolve set (the `AUTO_SELFRESOLVE_EXCLUDE` exclusion is hard and cannot be configured away); no `.env` read; no automatic npm publish; no automatic git push. The US-0092 AC-10 hard-stop class (`.env`, publish/push) and the US-0088 non-suppressible rules are unchanged.
9. **Segment-handoff notification non-suppressible (AC-6).** Under `AUTO_QUIET=1` the handoff/segment notification stays non-suppressible (US-0095 rule); only regular per-phase chatter is suppressed. Self-resolve and provider-switch events are recorded in the existing compact per-phase log and the block-retry ledger; no new screen or client.
10. **Stop-matrix + reason-code registration (AC-8).** The US-0088/US-0092 stop matrix gains exactly two rows: (row 1) active gate in the self-resolve set → bounded cause-resolution retry (one attempt per `(phaseId, gate)`) → `continue_same_phase`; (row 2) self-resolve exhausted / budget-cap → silent drain handoff, or hard stop when drain is unavailable. New reason codes registered: `SELFRESOLVE_ATTEMPT_EXHAUSTED`, `PROVIDER_SWITCH_APPLIED`, `PROVIDER_SWITCH_CAP_REACHED`, `SELFRESOLVE_DRAIN_HANDOFF`. `pause_request` stays hard; `decision_gate` stays propose-and-hold (terminal-continue exclusion intact).

**REJECTED:** (a) resetting the budget counter after a switch (PO fail-closed — provider cycling would manufacture budget); (b) auto-continue on `decision_gate` (propose-and-hold, no auto-flip, no `decision_gate=false` flip); (c) a new `MODEL_*` governance key for the switch (US-0132 boundary — `MODEL_*` ignored by `host_runtime_config_lib`); (d) a new provider-switch ledger surface (reuse the existing append-only names-only `handoffs/auto_block_retry/<run>.jsonl`); (e) a 5th new reason code for unknown gate id (reuse `HOST_CONFIG_INVALID`); (f) reopening US-0088/US-0092/US-0095/US-0101/US-0156 (compose by reference; additive-only); (g) a new screen/client (operator lock — existing compact per-phase log).

## Consequences

- `run_stop_matrix_json` gains the `--selfresolve-gate` branch + a self-resolve guard path; the parent/orchestrator write lock (DEC-0153) is unchanged (read-only; no `state.md`/`resume_brief.md` write, no `write_resume_pair`, `RESUME_BRIEF_AUTO_REFRESH` untouched).
- The OpenCode plugin honors the new payload: respawns the same phase once on `continue_same_phase`; performs the one-switch next-child model override on `PROVIDER_SWITCH_APPLIED`; runs the US-0095 7-step on `SELFRESOLVE_DRAIN_HANDOFF` when drain is enabled and an eligible OPEN story exists, else hard stop.
- Four new reason codes are registered; `HOST_CONFIG_INVALID` (existing) is reused for unknown gate ids.
- Five new default-off `AUTO_*` governance keys; absent-flag / all-default behavior is byte-identical to today (US-0156 AC style).
- Active/template pairs (`scripts/auto_outer_driver.py` ↔ `template/scripts/auto_outer_driver.py`; `.opencode/plugins/orchestrator.ts` ↔ `template/.opencode/plugins/orchestrator.ts`; `.opencode/agents/auto.md` ↔ `template/.opencode/agents/auto.md`; `.opencode/commands/auto.md` ↔ `template/.opencode/commands/auto.md`) stay byte-identical within each pair.
- `scripts/data/autonomy_stop_matrix.yaml` (DEC-0119 two-tier matrix) is NOT edited; the DEC-0153 write lock, US-0157/US-0158 continuation-pair repair, provider vendors, and the client surface are unchanged.
- Contract test `tests/us0164_selfresolve_stop_contract_test.py` with `test_us0164_*` markers (10 items) is authored in the next phase; this decision does not implement it.
- No `.env` read, no npm publish, no git commit/push occurs here. US-0164 stays **OPEN**; AC-1..AC-9 unchecked. No sprint is created.
