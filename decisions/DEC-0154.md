# DEC-0154: Additive US-0125 clone-guard line-cap reconciliation for the five BUG-0033 parity targets

- Date: 2026-10-08
- Status: Accepted
- Bug: `BUG-0033`
- Research: `R-0159` (DQ6)
- Amends: the US-0125 clone-guard **line-count** cap (and the `auto.md` ≤20 dispatch-only cap) for the five BUG-0033 parity-target files only. Composes with DEC-0153 (paired continuation) and the US-0156 `auto.md` re-addition.

## Context

US-0125's `test_us0125_clone_guard` asserts every `template/.opencode/commands/*.md` is `≤ 20` lines, and `test_us0125_auto_command_dispatch_only` asserts `auto.md ≤ 20`. BUG-0033 adds a diagnostics-only `## Stop conditions` + `## Fail-safe reason codes` pair to exactly five thin command bodies (closure/ask/auto/refresh-context/execute). After the locked R-0159 DQ1/DQ2 insert the projected line counts are closure 29, ask 19, auto 61, refresh-context 27, execute 34 — so closure and refresh-context **newly** cross the cap and auto/execute grow further; only ask fits. This is the single architectural input the fix depends on.

The cap's *intent* is "no 200-line Cursor clone", measured by **similarity ≤ 0.30** — which the DQ1 text does NOT breach (measured ≤ 0.031) and which introduces no US-0125 forbidden/clone/policy token. Only the line *count* cap is in tension, and the suite is **already red** on five pre-existing failures (R-0159 DQ6.1) — none caused by BUG-0033. The line-count cap is therefore not enforced-green anywhere in the suite today, and it has already been deviated from by the shipped US-0156 re-addition of `auto.md` (14→15 inventory, 49-line `auto.md`).

## Decision

1. **Adopt R-0159 DQ6 Option A (additive).** Amend `test_us0125_clone_guard` and `test_us0125_auto_command_dispatch_only` to raise the per-file line cap for the **five BUG-0033 parity-target files only** (a `BUG0033_PARITY_TARGETS` exemption set or a per-file cap of ~35), so AC-1..AC-5 (both headings present in all five files) are achievable.
2. **The clone-guard intent is preserved, not relaxed.** The **similarity ≤ 0.30** clone-guard, the **clone strip-list**, and the **frontmatter-shape marker** remain **INTACT for all files**. The exemption is on the line *count* alone, for the five named files, and only.
3. **This is an additive US-0125 contract amendment.** It is consistent with US-0125 being additive (backlog L5701) and with the shipped US-0156 `auto.md` re-addition, which is already a known deviation from the original 14-file / ≤20-line shape.
4. **Option B (re-scope to `ask.md`) and Option C (no cap change; accept new red) are REJECTED.** B fails AC-1/AC-3/AC-4/AC-5 and makes AC-8 unsatisfiable; C muddies "no regression" and leaves an unexplained cap breach. If `/execute` cannot satisfy the reconciliation it must raise an **operator decision_gate** (re-scope, Option B) — it may NOT silently accept Option C.

## Consequences

- The US-0125 clone-guard now has a **per-file line-cap exemption set** = `{closure, ask, auto, refresh-context, execute}.md` (the five BUG-0033 parity targets); all other `template/.opencode/commands/*.md` files keep the ≤20-line rule. The similarity ≤ 0.30 guard, strip list, and frontmatter-shape marker are unchanged for every file.
- The amendment is **additive and non-regressing**: it introduces no new *marker-level* failure and changes no similarity/clone/policy behavior. It is a seed task (T-002) in the `# BUG-0033` architecture H1, executed by `/execute`.
- No reason-code, runbook, stop-matrix, repair-ledger, `tui.json`, config, or scratchpad mutation is authorized by this decision. The `.cursor/commands/*` rich files remain read-only reference sources. No broad handoff grant, JSON command template, TUI/RPC/localhost route, or status/acceptance mutation is authorized.
