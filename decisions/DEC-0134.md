## Context

US-0133 shipped `standalone/` + `AgentKernel`. The standalone runtime still cannot consume shipped Python validators or canonical repo artifacts. US-0134 must add a host-neutral `KernelBridge` that locates the current kit/project kernel, checks an explicit runtime→kernel range, fail-closes with four `KERNEL_*` codes, and invokes named Python CLIs without rewriting their semantics or extracting `its-magic-kernel/`.

R-0122 locked DQ1–DQ10 and recommended **A1**. This DEC accepts A1 and closes architecture-owned items: KernelBridge TypeScript surface, manifest field names, `semver` pin, `status_reconcile_validate.py` schema, installer allowlist shipping, and the ten `test_us0134_*` markers. It also closes research-critic informational NBs (`us0134rsc-*`).

### 2. Package + import boundary (DQ10 / AC-1)

- Path: **`standalone/packages/kernel-bridge`**. npm name `@its-magic/kernel-bridge`, `private: true`, `version: 0.0.0`, `type: module`, `engines.node >=22.19.0`, export `./src/index.ts`.
- **No Pi imports.** `package.json` must not depend on `@earendil-works/pi-*` or `@its-magic/pi-kernel`. Existing Biome `noRestrictedImports` already denies Pi outside `pi-kernel`; extend the US-0133 grep to also deny Pi inside `kernel-bridge`. Do **not** add a Biome override for `kernel-bridge`.

### 3. Locate algorithm (DQ1 / AC-1)

Walk up from `process.cwd()` (and, if cwd is inside `standalone/`, also from the `standalone/` directory) until a **kernel root** is found or the filesystem root / **cap 16** is hit.

A directory is a kernel root iff **all** of:

1. `docs/product/backlog.md`
2. `scripts/intake_evidence_validate.py`
3. `its_magic/.its-magic-version`

**Explicit override**: `locateProjectKernel({ kernelRoot })` / CLI `--kernel-root <abs>`. The path must still pass the three markers; failure → `KERNEL_NOT_FOUND` (not a silent accept).

`locateMode`: `kit-dev` when `standalone/package.json` exists as a child of the kernel root; else `consumer`. Do not require `standalone/` for consumer locate.

**Reject**: postinstall scratchpad-or-version walk; walk-from-`standalone/` only; filename-only `*kernel*` inference.

### 4. Version + manifest + range (DQ2 / DQ3 / AC-2)

| Method | Source |
|---|---|
| `getKernelVersion()` | `its_magic/.its-magic-version` (DEC-0045; trim; no second version file) |
| `readContractManifest()` | `its_magic/kernel-contract.json` (additive kit + template file) |

Locked manifest schema:

```json
{
  "schema_version": 1,

  "validators": ["intake_evidence_validate", "bug_issue_validate", "pack_json_validate", "validate_closure_verification", "ledger_validate", "model_tier_validate", "uat-planner", "status-reconcile"],

```

`kernel_version` must match the version file or → `KERNEL_CONTRACT_MISMATCH`. Missing/malformed manifest after successful locate → `KERNEL_CONTRACT_MISMATCH`. Do **not** synthesize a silent default from filenames.

Runtime range file `standalone/packages/kernel-bridge/supported-kernel-range.json`:

```json
{
  "minInclusive": "0.1.3-9",
  "maxExclusive": "0.2.0",
  "includePrerelease": true
}
```

Compare **only** inside `kernel-bridge`:

`semver.satisfies(version, '>=' + minInclusive + ' <' + maxExclusive, { includePrerelease: true })`

Pin: **`semver@7.8.5`** (exact) + `@types/semver@7.8.0` on `kernel-bridge` only — not `pi-kernel`, not kit npm `its-magic`. v1 requires `includePrerelease: true` so kit marker `0.1.3-9` is in range. **Reject** putting the range in `RuntimeConfig` (US-0138).

Installer: `its_magic/` is already an install-include directory; execute ships `its_magic/kernel-contract.json` + `template/its_magic/kernel-contract.json`. Upgrade copies the new file; missing manifest on old installs fail-closed (`KERNEL_CONTRACT_MISMATCH`), never silent-default (R3).

### 5. KernelBridge TypeScript surface (D3 / AC-1) — LOCKED

Owned types live in `packages/kernel-bridge`. Workflow / `apps/cli` import **only** these types — never spawn Python themselves.

```ts
type LocateMode = "kit-dev" | "consumer";

type KernelHandshakeCode =
  | "KERNEL_NOT_FOUND"
  | "KERNEL_VERSION_UNSUPPORTED"
  | "KERNEL_VALIDATOR_MISSING"
  | "KERNEL_CONTRACT_MISMATCH";

class KernelBridgeError extends Error {
  readonly code: KernelHandshakeCode;
  readonly evidence?: string;
}

interface LocateResult {
  kernelRoot: string;
  locateMode: LocateMode;
}

interface ContractManifest {
  schema_version: 1;
  kernel_version: string;
  validators: string[];
  artifact_keys: string[];
}

type ArtifactKey =
  | "vision" | "backlog" | "acceptance" | "architecture"
  | "decisions_index" | "research" | "state" | "decisions_dir"
  | "sprints" | "handoffs" | "release_queue" | "release_notes"
  | "traceability" | "work_packs" | "sovereign";

interface ValidatorResult {
  name: string;
  pass: boolean;           // exit 0
  exitCode: number | null;
  reasonCode: string | null; // first [A-Z][A-Z0-9_]+ from stderr
  stdout: string;
  stderr: string;
  evidence: string | null;   // VALIDATOR_TIMEOUT | VALIDATOR_CRASH | null
}

interface KernelBridge {
  locateProjectKernel(opts?: { cwd?: string; kernelRoot?: string }): Promise<LocateResult>;
  getKernelVersion(kernelRoot?: string): Promise<string>;
  readContractManifest(kernelRoot?: string): Promise<ContractManifest>;
  resolveArtifactPaths(kernelRoot?: string): Promise<Record<ArtifactKey, string | null>>;
  runValidator(name: string, args?: string[], kernelRoot?: string): Promise<ValidatorResult>;
  runUatPlanner(args?: string[], kernelRoot?: string): Promise<ValidatorResult>;
  runStatusReconcile(args?: string[], kernelRoot?: string): Promise<ValidatorResult>;
}
```

Handshake order (fail-closed; first match wins):

1. locate fails three-marker / override → `KERNEL_NOT_FOUND`
2. version empty/unparseable as semver → `KERNEL_CONTRACT_MISMATCH`
3. parsed version outside range → `KERNEL_VERSION_UNSUPPORTED`
4. manifest missing/malformed / `kernel_version` ≠ version file → `KERNEL_CONTRACT_MISMATCH`
5. required artifact path missing → `KERNEL_CONTRACT_MISMATCH`
6. `runValidator` unknown name / missing script / missing interpreter → `KERNEL_VALIDATOR_MISSING`

Validator semantic FAIL (exit ≠ 0) and timeout/crash are **not** a fifth `KERNEL_*` code (D5). They return `ValidatorResult.pass=false` with `reasonCode` / `evidence`. Callers must not advance (D7 / AC-4).

### 6. Named validator inventory + spawn (DQ4 / DQ5 / AC-4)

Allowlist (unknown name → `KERNEL_VALIDATOR_MISSING`). Manifest `validators[]` **intersects** this list; manifest cannot enable unknown names.

| `status-reconcile` | `scripts/status_reconcile_validate.py` (new, read-only) |

**Process invocation (LOCKED):**

- Interpreter discovery (first that probes `python -c "import sys; raise SystemExit(0 if sys.version_info[0]==3 else 1)"` with `shell: false`): `ITS_MAGIC_PYTHON` / `PYTHON` / `PYTHON_BIN` → win32 `py -3` then `python` then `python3` → posix `python3` then `python`.
- **After a successful probe, spawn the resolved interpreter path** (real `python.exe` / `python3`), not the Windows `py -3` launcher, so timeout kill cannot orphan an interpreter (R2 / PEP-0397).
- `cwd` = kernel root. `windowsHide: true`. `shell: false`. Timeout default **60s** via `spawn` `timeout` + `AbortSignal.timeout` (Node 22, Context7-confirmed). Capture stdout/stderr UTF-8 (`maxBuffer` 1 MiB).
- Exit **0** → PASS. Exit **non-zero** → FAIL; first `[A-Z][A-Z0-9_]+` token from stderr is the **Python** reason (US-0125 compose: raw codes, no `OPENCODE_*`).
- Cannot spawn interpreter / ENOENT on script → `KERNEL_VALIDATOR_MISSING`.
- Timeout / signal / crash → `VALIDATOR_TIMEOUT` / `VALIDATOR_CRASH` evidence strings. Not a fifth handshake code.

**Reject**: postinstall `python` vs `python3` only; `OPENCODE_DRIVER_INVOKE_FAILED` on the standalone path; wrapping all 40+ `scripts/*.py`.

### 7. Artifact map (DQ6 / AC-5)

Paths relative to kernel root. **Required** (missing → `KERNEL_CONTRACT_MISMATCH`): vision, backlog, acceptance, architecture, decisions_index, research, state, decisions_dir, sprints, handoffs. Optional (`null` if absent): `work_packs`, `sovereign`, plus `release_queue` / `release_notes` / `traceability` may resolve to the canonical path even when optional-empty is allowed for release files — **required set is the ten listed above**; release/traceability/work/sovereign follow R-0122 DQ6 (traceability hot surface = `docs/engineering/state.md`; work/sovereign optional).

Pi session history is never a map entry. No SQLite paths. Do not relocate lifecycle state.

### 8. `runUatPlanner` / `runStatusReconcile` (DQ7)

Both are required §16.1 methods implemented as thin `runValidator` aliases:

- `runUatPlanner(args)` → `runValidator('uat-planner', args)` → existing `scripts/uat_probe_lib.py`. Args pass through unchanged (tests use `--self-test` for a PASS fixture). Does **not** invent a TypeScript UAT planner (US-0142).
- `runStatusReconcile(args)` → `runValidator('status-reconcile', args)` → new `scripts/status_reconcile_validate.py`.

**`status_reconcile_validate.py` schema (architecture-owned):**

- CLI: `--kernel-root PATH` (default cwd). Extra args ignored except `--kernel-root`.
- Read-only checks that all exist and contain at least one markdown heading (`^#{1,6} `): `docs/product/backlog.md`, `docs/product/acceptance.md`, `docs/engineering/state.md`, `handoffs/resume_brief.md`.
- Exit 0 → stdout `[STATUS_RECONCILE_VALIDATE_OK]`.
- Exit ≠ 0 → stderr `STATUS_RECONCILE_SURFACE_MISSING` or `STATUS_RECONCILE_PARSE_FAILED`.
- **Never writes** those surfaces (tests assert no mtime/content mutation). Does not perform curator `/status-reconcile`.

**Reject**: no-op PASS; porting the curator command into TS.
