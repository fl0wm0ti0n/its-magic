# DEC-0150: Project-scoped production runtime host

- Date: 2026-09-19
- Status: Accepted
- Story: `US-0150`
- Research: `R-0150`

## Context

The standalone package implementations exist, but the public CLI and daemon construct throwing kernels and empty configuration while some services report placeholder success. Operators therefore cannot use the delivered contracts as one real standalone runtime.

## Decision

Adopt `@its-magic/runtime-host` in `standalone/packages/runtime-host` as the only production composition root. `createRuntimeHost({ projectRoot, lifetime })` resolves configuration once, admits the kernel bridge, creates the custom-tool-only Pi kernel, session supervisor, real ToolBroker, intelligence/context services, operational store, and existing command router.

The host is scoped to one project. The daemon owns it for process lifetime; direct CLI invocations dispose it in `finally`. Leaf packages and `runtime-core` do not import `runtime-host`. Test factories are explicit and cannot become production defaults.

## Consequences

- CLI and daemon must consume the same host and remove local throwing kernels, literal empty config, and synthetic success paths.
- Admission failures return redacted, fail-closed `RUNTIME_*` results before workflow work begins.
- Repository artifacts and validators remain canonical; SQLite stays operational only.
- TUI transport, browser/app services, deployment, and CI operator-path proof remain separately owned by US-0151 through US-0154.

## Verification

`test_us0150_*` proves one config resolution, real Pi custom-tool session admission, policy-admitted tool execution or denial, bridge/validator preservation, unavailable-service failures, CLI/daemon host usage, and disposal. Tests use a deterministic local model seam and no paid credentials.
