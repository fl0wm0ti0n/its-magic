# DEC-0153: Phase-child-owned paired continuation record for BUG-0035

- Date: 2026-10-03
- Status: Accepted
- Bug: `BUG-0035`
- Research: `R-0157`
- Amends: DEC-0069 only for the research-to-architecture writer gap; composes with DEC-0038 and DEC-0152.

## Context

DEC-0069 correctly keeps a present stale resume brief fail-closed, but the
research-to-architecture boundary has no authorized writer for its mandatory
state/brief pair: the completed tech-lead child owns the state checkpoint and
the spawn-only parent owns neither phase artifact nor the brief. This is an
ownership defect, not authority to accept stale evidence or to repair it from
state.

## Decision

1. The completed, canonical phase child is the only writer of its paired
   continuation update. For BUG-0035 the tech-lead child receives exactly one
   additional allow: `handoffs/resume_brief.md`. The active and template
   tech-lead maps must be byte-identical, retain `"**": deny` before specific
   allows, and gain no other permission. The auto parent remains `edit: deny`.
2. The child writes its canonical state checkpoint first. Only after it has
   constructed and validated the same continuation tuple does it atomically
   replace/prepend the resume latest-pointer block. Cross-file atomicity is not
   claimed: an incomplete pair is invalid and stops.
3. The pair key is
   `orchestrator_run_id|work_item_kind|bug_id|completed_phase|runtime_proof_id`.
   Both sides must exactly agree on writer role, resolution source, effective
   plan, skipped/completed phases, next phase/role, cursor, budget, stop reason,
   fresh marker, and every strict-proof field. Exact same-key replay is a no-op;
   any changed same-key field, proof/marker reuse, malformed/missing side,
   conflict, or unauthorized writer fails closed.
4. Syntax failure is `RESUME_BRIEF_UNPARSEABLE`; stale, absent-required,
   conflicting, authorization, replay, or proof/isolation-invalid continuation
   evidence is `RESUME_BRIEF_STALE` with the underlying predicate retained.
   Neither state fallback nor a next spawn is allowed while a brief is present
   but invalid. `RESUME_BRIEF_AUTO_REFRESH=0` remains an absolute prohibition.

## Consequences

- The parent remains read/validate/spawn-only; a completed child alone never
  authorizes advancement.
- The implementation must add fixture/mock contract coverage for the seven
  BUG-0035 AC groups, active/template permission parity, and runbook remediation
  that preserves evidence and requests a new authorized child rather than a
  hand edit or reconciler.
- No broad handoff grant, all-role grant, bridge writer, autonomous reconciler,
  JSON command template, TUI/RPC/localhost route, configuration change, or
  status/acceptance mutation is authorized by this decision.
