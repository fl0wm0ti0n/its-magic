# DEC-0151: Version-pinned OpenCode `/auto` Markdown command integration

- Date: 2026-09-26
- Status: Accepted
- Bug: `BUG-0030`
- Research: `R-0152`

## Context

The installed OpenCode host is `1.18.32`. its-magic routes `/auto` through an
undocumented TUI RPC bridge, so the required peer brand is absent and invocation
ends at `OPENCODE_AUTO_TUI_DEFINED_UNBRANDED` before the auto agent starts.

## Decision

Support the documented OpenCode `1.18.32` command contract only. The
framework-owned `.opencode/commands/auto.md` uses `agent: auto` frontmatter and
contains the canonical spawn-only orchestration prompt. OpenCode owns command
registration, session selection, prompt admission, cancellation, and delivery.

`@opencode/plugin@1.18.32` is unavailable, so `Plugin.define`,
`ctx.command.transform`, and `ctx.session.switchAgent` are not a supported v1
implementation choice. The private RPC bridge and TUI plugin entry are removed
from the `/auto` route. The existing `auto` agent remains the spawn-only
lifecycle owner.

## Consequences

- Consumer upgrades replace the framework-owned command and remove managed
  legacy TUI/RPC artifacts without overwriting unrelated user configuration.
- A real host integration check invokes `/auto` and proves agent selection and
  durable prompt admission before any model result.
- This decision supersedes the BUG-0023/BUG-0024 private-RPC route only; their
  historical artifacts remain unchanged.
