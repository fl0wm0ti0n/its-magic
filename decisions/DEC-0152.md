# DEC-0152: OpenCode command-owned continuous auto lifecycle

- Date: 2026-09-27
- Status: Accepted
- Story: `US-0156`
- Research: `R-0153`

## Context

The documented OpenCode 1.18.32 route selects `agent: auto` from the
framework-owned Markdown command. The retired TUI/RPC path is not a supported
command-dispatch mechanism. The current first-phase bridge can silently select
`execute` after a resolver failure, and it does not carry an effective phase
plan, a next-segment cursor, or idempotent continuation provenance.

## Decision

The Markdown command and primary `auto` agent own one sequential, spawn-only
parent lifecycle. The parent resolves the work item and effective phase plan
before creating a fresh role Task for each phase. It continues only after the
canonical Stop-Matrix returns an explicit continuation action.

Resolution order is explicit `start-from`, validated `resume_brief`, then
validated `state.md`. Resolver, policy, plan-intersection, scheduler, or
provenance errors fail closed; no path may fall back to `execute`. Explicit
`bug-target` selects the bug scheduler; otherwise story drain selects eligible
OPEN stories. A story drain and bug queue conflict fails closed.

The bridge-owned state/resume protocol records an idempotent continuation tuple:
run ID, work-item kind and ID, phase plan, skipped phases, completed and next
phase, cursor/budget, stop reason, and fresh child isolation reference. Direct
manual phase persistence remains separate and cannot establish `/auto` child
completion.

## Consequences

- `.opencode/commands/auto.md` and the `auto` agent remain the only OpenCode
  command route; no TUI/RPC restoration, JSON command template, or localhost
  endpoint is allowed.
- Role permission maps put their broad deny rule before path-specific allows,
  because OpenCode uses the last matching rule. This preserves deny-by-default
  while enabling each role's owned artifact paths and the auto agent's Task
  allowlist.
- The existing Stop-Matrix, quality/release gates, caps, and secret boundaries
  remain authoritative. A completed child alone never permits another spawn.
- US-0156 cannot close until BUG-0022 and BUG-0027 are DONE and verify-work
  cites them. BUG-0028 and BUG-0029 remain independently OPEN unless their own
  work closes them.

## Verification

`test_us0156_*` must cover command/agent ownership, fresh sequential child
sessions, fail-closed resolution without `fallback_execute`, plan intersection,
scheduler precedence and conflict, Stop-Matrix actions/caps, idempotent
resume, DoD prerequisites, and active/template/installer parity.
