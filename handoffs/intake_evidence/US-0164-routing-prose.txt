## US-0164 — Gate cause resolution and autonomy continuity

Summary: As an operator, I want the AI to resolve the cause of an active gate and continue the same run without an operator or auto re-invoke. The gate itself is never bypassed, weakened, or disabled. The safety floor stays non-negotiable in every configuration: pause_request and gate-override forbidden remain hard stops, no .env read, no automatic npm publish or git push. Self-resolve gates are configured per gate (comma list, default empty). Budget gates get a provider fallback with at most one provider switch per run from the local catalog, after which the run hands off to backlog drain silently; the budget counter is not reset. With drain disabled or no OPEN story the run remains a hard stop (fail-closed). Segment handoff notifications stay non-suppressible even under AUTO_QUIET=1. All new configuration is default-off: without explicit activation the behavior is byte-identical to today.
